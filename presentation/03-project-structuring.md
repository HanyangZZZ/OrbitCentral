# Project Structuring

> **Source:** [03-project-structuring.png](03-project-structuring.png)

## Class Organization

Many languages are Object-Oriented Programming (OOP), which can be conveniently divided into class systems. To make your code navigable for judges, it is highly recommended that your source code is organized properly.

### Things to Look Out For:

- **Proper naming conventions** (based on the language(s) you're using)
- **Class grouping** by similar functionality
- **Inheritance** where applicable, little/no redundant code/class files
- **Organization by folder**, where applicable
- **Frontend-backend structure**
- **Multi-language categorization**
- **Indication of black-box methods**

---

## Language Use

In your project, feel free to use **multiple languages** that you believe will best fit the specific task you're working on. Be sure to follow all naming conventions for each individual language.

---

## Comments

Proceeding all methods, files, and classes, **comments must be filled out**. Comments are to describe the function of the given section of code, and all necessary copyright or citation documentation.

---

## Project Report

It is preferable for your project report to be **aligned with the order of your source code**. Indicate at the top of each source code file the correlation with a respective project report header.

---

## Presentation Setup

When you enter the judging space:

- Have all materials ready so you can share your presentation as soon as you join.
- If you have more than one member, **nominate one person to share the screen**.
- If your program contains external APIs or connects to any external software beyond your source code, **have the inner workings of that system ready to explain**.
