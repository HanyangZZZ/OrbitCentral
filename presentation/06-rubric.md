## Slideshow Structure & Breakdown

The presentation slides should be organized in the following order:

### 1. Cover & Problem Context — 5% of overall slideshow

| Slide | Content |
|-------|---------|
| **Cover Title Page** | Project name, team members, date |
| **Problem Statement & Opportunity** | Present as a **two-hills visual**: Hill 1 = the current state, Hill 2 = the ideal state. Identify the **gap** between them, then position your **opportunity as the bridge** connecting the two hills. |
| **Statistics** | Data and figures that support the existence/severity of the problem |
| **Target Market Segmentation** | Who are the users? Demographics, behaviors, needs |
| **Market Need** | Why does this market need a solution like yours? |

### 2. Our Solution — 5% of overall slideshow

Discuss how your solution solves the problem:

| Slide | Content |
|-------|---------|
| **Name & Slogan** | The brand name and tagline |
| **Unique Selling Proposition (USP)** | What sets your product apart from competitors |
| **Brand Positioning Chart** | Visual chart showing where your brand sits relative to competitors |

### 3. Software Concept — 10% of overall slideshow

- The concept of the software and what makes it stand out
- Key differentiators and innovation
- Why your approach is the best fit for the problem

### 4. Website Structure & Design Process — 10% of overall slideshow

- Overall website/application architecture
- Design process and methodology
- **UI Design** — wireframes, mockups, and final interface design
- Frontend-backend structure overview

### 5. Feature Explanations — 70% of overall slideshow

This is the **majority** of the presentation. The **usability and functionality** of the program must be demonstrated live.

For **each** feature below, you must clearly explain:

- **Logical Workflow** — step-by-step how the feature works
- **Scalability** — how it handles growth
- **Security** — protections and safeguards in place
- **User Engagement** — how it improves the user experience
- **APIs & Tools Used** — external services and libraries leveraged
- **Main Data Storage Methods** — database design and storage approach
- **Coding Context** — provide sufficient context behind the chosen coding program and conventions (language choices, design patterns, why they fit this feature)

#### Features to Cover:

| # | Feature | Key Points |
|---|---------|------------|
| 1 | **Sorting Businesses by Category & Filtering** | Category taxonomy, filter logic, query optimization |
| 2 | **Sorting Businesses by Reviews or Ratings** | Sorting algorithms, weighted scoring, real-time updates |
| 3 | **Saving & Bookmarking Favorite Businesses** | User-specific storage, persistence, sync across sessions |
| 4 | **Allowing Users to Leave Reviews or Ratings** | Review submission flow, validation, moderation |
| 5 | **Display Special Deals / Coupons** | Deal management, expiration logic, display strategy |
| 6 | **reCAPTCHA Verification Step to Prevent Bot Activity** | Bot prevention flow, reCAPTCHA integration, fallback handling |
| 7 | **Cookies** | Cookie usage, session management, consent handling |

### 6. Conclusion

| Slide | Content |
|-------|---------|
| **Limitations of the Program** | Honest assessment of current constraints and trade-offs |
| **Timeline to Implement the Program** | Realistic development milestones and roadmap |
| **References** | All external sources, APIs, libraries, and credits |

## Project Report Requirements

### Deliverables (supporting materials, not the priority)

The report should also contain:

- **README file**
- **Source code**
- **Documentation of templates/libraries used**
- **Documentation of copyrighted material used**

> These are supporting deliverables — they should be included but are not the main focus of scoring.

### Report–Code Alignment

The project report must be **aligned with the source code names** — they should be synced. Indicate at the **top of each source code file** the correlation with a respective project report header, so judges can easily cross-reference between the report and the codebase.

## Detailed Scoring Criteria

### A: Prompt

1. Demonstrate understanding of the given coding prompt.
2. Adhere to prompt guidelines and address issues addressed.
3. Properly utilize tools and APIs as needed.
4. Understand how proper techniques help to devise a solution (conditional statements, loops, OOP).
5. Analyze the market and the need for the project.
6. Utilize appropriate coding languages to suit the project's needs.

### B: Project Format

1. Provide necessary files and documentation used for project code.
2. Test and review code to ensure a working, bug-free program.
3. Create a repository for all code on a proper platform (GitHub).
4. Organize information in an easily understandable manner (folders, naming conventions, inheritance, etc.).
5. Include commenting and adequate documentation.

### C: Presentation

1. Describe different aspects and features of the project code with detail.
2. Demonstrate the ability to effectively answer questions and tactfully interact with the judges.
3. Present with self-confidence and a projected voice.
4. Plan presentation to include all key aspects of presentation rubric.
